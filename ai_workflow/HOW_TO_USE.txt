==============================================================================
AI WORKFLOW MODULE - BACKEND DEVELOPER INTEGRATION GUIDE
==============================================================================

1. OVERVIEW
------------------------------------------------------------------------------
The `ai_workflow` module provides real-time disaster tweet analysis for social
media monitoring during emergency events (floods, wildfires, storms, etc.). It
evaluates incoming tweets to filter out noise/sarcasm, classifies relevance,
determines emergency category and severity levels, extracts specific place mentions,
and geocodes location coordinates for Leaflet interactive mapping. Supports English
and French disaster reports.


2. ENVIRONMENT VARIABLES & API KEY WIRING
------------------------------------------------------------------------------
`ai_workflow` is pre-wired to load `HACKATHON_API_KEY` from `backend/.env` or
system environment variables using python-dotenv.

Environment variable check order:
  1. HACKATHON_API_KEY (primary)
  2. GEMINI_API_KEY    (fallback)
  3. GOOGLE_API_KEY    (fallback)

Official Hackathon Proxy Endpoint:
  - Base URL: https://hackathon-api-new-152590733511.northamerica-northeast2.run.app
  - Endpoint: POST /api/generate
  - Header:   X-API-Key: <HACKATHON_API_KEY>

Note: If no API key is present or network calls fail, `ai_workflow` automatically
falls back to its built-in zero-shot NLP rule engine so the application runs
reliably offline without throwing errors or crashing.


3. REQUIRED DEPENDENCIES
------------------------------------------------------------------------------
Install module dependencies using requirements.txt:

  pip install -r ai_workflow/requirements.txt

Core dependencies:
- fastapi, uvicorn, pydantic (REST API server)
- pandas (CSV batch processing)
- python-dotenv (environment variable loading)
- requests (Gemini REST API calls & HTTP geocoding)


4. HOW TO INTEGRATE INTO BACKEND (backend/app/ai.py)
------------------------------------------------------------------------------
To connect `ai_workflow` into `backend/app/ai.py`, import `analyze_tweet` or
use the batch prompt helpers:

--------------------------------------------------
Option A. Plug-and-Play Batch Classification for `backend/app/ai.py`:
--------------------------------------------------
```python
import sys
import os
sys.path.append(os.path.abspath("ai_workflow"))
from analyzer import analyze_tweet

CATEGORY_MAP = {
    "infrastructure_damage": "infrastructure_damage",
    "evacuation": "evacuation",
    "request_for_help": "rescue_help",
    "medical_need": "rescue_help",
    "volunteer_relief_effort": "donations_volunteering",
    "official_update": "weather_water_levels",
    "general_concern": "sympathy_support",
    "other": "other_related",
}

def classify_batch(texts: list[str]) -> list[dict]:
    results = []
    for text in texts:
        res = analyze_tweet(text, geocode=False)
        cat = res.get("category")
        mapped_cat = CATEGORY_MAP.get(cat, "other_related") if res.get("is_relevant") else None
        results.append({
            "relevant": res.get("is_relevant", False),
            "confidence": res.get("relevance_confidence", 0.5),
            "category": mapped_cat,
            "severity": res.get("severity"),
            "locations": [loc["raw_text"] for loc in res.get("locations", [])],
            "reasoning": res.get("reasoning", "")
        })
    return results
```


--------------------------------------------------
Option B. LLM Batch Prompt Helper: `format_batch_prompt(tweets: list)`
--------------------------------------------------
Formats 50-100 tweets into a single prompt for Gemini to classify in ONE API call:

```python
from prompt_template import format_batch_prompt
from analyzer import call_hackathon_gemini_api

prompt = format_batch_prompt(tweets)
json_text, remaining_quota = call_hackathon_gemini_api(prompt)
```

Note for AI / Backend Teammates:
  * Your BATCH_RESPONSE_SCHEMA causes HTTP 500 on the hackathon API (it doesn't accept ["string","null"] types), so the backend uses its own schema with your prompt. Also, format_batch_prompt IDs start at 1 when you pass plain strings.


--------------------------------------------------
Option C. LLM Situational Overview: `format_summary_prompt(tweets: list)`
--------------------------------------------------
Generates a 3-5 sentence prose situation overview for emergency responders:

```python
from prompt_template import format_summary_prompt
from analyzer import call_hackathon_gemini_api

prompt = format_summary_prompt(relevant_tweets)
summary_text, remaining_quota = call_hackathon_gemini_api(prompt)
```


--------------------------------------------------
Option D. Single Tweet Analysis: `analyze_tweet(text: str, geocode: bool = True)`
--------------------------------------------------
Evaluates a single tweet and enriches location mentions with geocoded lat/lng:

```python
from analyzer import analyze_tweet

result = analyze_tweet("Water entering home on Elbow River in High River! Family trapped upstairs #sos #abflood")
# Output:
# {
#   "is_relevant": True,
#   "relevance_confidence": 0.95,
#   "category": "request_for_help",
#   "severity": "critical",
#   "locations": [
#     {"raw_text": "High River", "lat": 50.5806, "lng": -113.8681},
#     {"raw_text": "Elbow River", "lat": 51.0333, "lng": -114.05}
#   ],
#   "reasoning": "Tweet indicates an urgent call for emergency assistance or rescue."
# }
```


5. KNOWN LIMITATIONS & TIPS FOR BACKEND TEAM
------------------------------------------------------------------------------
1. Hackathon API Schema Note: `BATCH_RESPONSE_SCHEMA` causes HTTP 500 on the hackathon API (it doesn't accept ["string","null"] types), so the backend uses its own schema with your prompt. Also, format_batch_prompt IDs start at 1 when you pass plain strings.
2. Quota Preservation: The Hackathon Gemini quota is 1,000 total requests. Use
   `format_batch_prompt()` (50 tweets per call) to process entire datasets in
   ~20-30 API calls instead of thousands of single calls.
   QUOTA LOCK: analyze_tweet() / analyze_tweet_llm() make ONE request PER TWEET,
   so they only call Gemini when ALLOW_PER_TWEET_LLM=1 is set on purpose.
   Without it, batch_processor.py and app.py use the free NLP engine. Only turn it
   on for a handful of tweets. For whole datasets, use the backend (it batches).
3. Geocoding Rate Limits: Nominatim geocoding defaults to 1 request/sec when
   querying OpenStreetMap. `ai_workflow` includes an offline gazetteer cache
   for major Canadian disaster locations (Calgary, High River, Fort McMurray,
   Lethbridge, Peguis First Nation, Siska First Nation, Selkirk) to avoid delays.
4. Fallback Guarantee: `analyze_tweet()` will never throw an unhandled exception.
   If Gemini API returns an error or times out, it automatically falls back
   to the zero-shot NLP classifier.

6.2 What the backend imports from ai_workflow (please don't rename these)
  - analyzer.analyze_tweet_nlp(text)
      Per-tweet fallback when Gemini is off, over budget or fails. The backend
      reads: is_relevant, relevance_confidence, category, severity,
      locations[].raw_text, reasoning. The categories must stay the same 8:
      infrastructure_damage, evacuation, medical_need, request_for_help,
      official_update, volunteer_relief_effort, general_concern, other.
  - prompt_template.format_batch_prompt(tweets)
      Used for every Gemini batch (50 tweets per request). The backend passes
      [{"id": 0, "text": ...}, {"id": 1, ...}] with explicit 0-based ids and
      matches results back by id, so keep supporting dict input with "id".
  - prompt_template.format_summary_prompt(tweets)
      Used for the AI summary button (one request per click, cached).
  - geocoder.KNOWN_GAZETTEER
      The backend geocoder checks this first (instant, no network), then
      OpenStreetMap. Adding places here improves the map for free.

6.3 What the backend does NOT use
  - BATCH_RESPONSE_SCHEMA: the hackathon API returns HTTP 500 for it, so the
    backend sends its own schema (backend/app/ai.py, _BATCH_SCHEMA) with the
    same fields and the same 8 categories, plus "none" instead of null.
  - analyze_tweet(), analyze_tweet_llm(), call_hackathon_gemini_api(),
    geocoder.resolve_locations(), batch_processor.py, app.py.

6.4 Things to know when you change prompts
  - BONUS CHALLENGE UPDATE (CE Strategies 61,159-tweet global dataset):
    * "is_relevant" now strictly means FLOOD-RELATED for both Alberta & Bonus datasets.
      Non-flood disasters (explosions, shootings, fires, earthquakes, haze, storms without water) are is_relevant: False.
    * New field on every output object: "disaster_type" (flood, storm, wildfire, earthquake, explosion, shooting, transport_accident, haze, other, none).
    * Locations outside Canada MUST include country ("Tacloban, Philippines", "Brisbane, Queensland, Australia").
    * format_summary_prompt() summarizes BY country/region ("Philippines: ... Australia: ...") in 3-6 sentences of plain prose.
    * KNOWN_GAZETTEER enriched with major global flood locations (manila, tacloban, brisbane, jakarta, new orleans, bangkok, dhaka, chennai, kerala, etc.).
  - Any edit to analyzer.py, prompt_template.py or geocoder.py changes the
    backend's "fingerprint" and makes backend/data/sample_seed.json stale.
    The deployed server then rebuilds the sample with the free NLP engine
    (never with Gemini, so no quota is spent), and the backend team re-runs
    the Gemini sample once (~410 requests for Alberta + Bonus). Tell the backend team when a
    prompt change is final, so this only happens once.
  - Batch output must stay a JSON array of
    {id, is_relevant, relevance_confidence, category, severity, disaster_type, locations: [str], reasoning}.
  - Locations: specific places, city/province/country added when clear
    ("Mission, Calgary, Alberta", "Tacloban, Philippines"). No bare provinces or countries.
